# Test Plan: SauceDemo


## 1. Введение
Данный документ описывает стратегию, объем и подход к тестированию веб-приложения SauceDemo (https://www.saucedemo.com/). 
SauceDemo — учебный сайт интернет-магазина, предназначенный для практики тестирования.

## 2. Цели тестирования
- Проверить работоспособность основных пользовательских сценариев (вход, просмотр товаров, корзина, оформление заказа).
- Выявить и задокументировать дефекты (баги) в поведении интерфейса и логике работы.
- Убедиться, что система корректно обрабатывает негативные сценарии (неверный ввод, пустые поля).

## 3. Область тестирования (In Scope)
- **Модуль аутентификации (Login):** вход с разными типами пользователей (standard, problem, locked_out).
- **Модуль каталога (Inventory):** отображение списка товаров, сортировка, добавление в корзину.
- **Модуль корзины (Cart):** просмотр добавленных товаров, удаление, переход к оформлению.
- **Модуль оформления (Checkout):** ввод данных пользователя (First Name, Last Name, Zip Code), завершение заказа.

## 4. Вне области тестирования (Out of Scope)
- Тестирование реальных платежных систем (в SauceDemo оплата симулируется).
- Тестирование производительности (нагрузочное тестирование).
- Тестирование безопасности (penetration testing).
- Кросс-браузерное тестирование (в рамках данного проекта тестирование проводится только в Google Chrome).

## 5. Тестовое окружение
- **ОС:** Windows 10/11 (или ваша ОС).
- **Браузер:** Google Chrome (актуальная версия).
- **Тестовые данные:** предустановленные аккаунты SauceDemo (`standard_user`, `problem_user`, `locked_out_user`, пароль `secret_sauce`).

## 6. Стратегия тестирования
- **Функциональное тестирование:** проверка соответствия работы системы требованиям (ручное).
- **Негативное тестирование:** проверка поведения системы при вводе некорректных данных.
- **Исследовательское тестирование:** свободное изучение интерфейса под аккаунтом `problem_user` для поиска специфичных дефектов.
- **API-тестирование (автоматизация):** написание базовых автотестов (pytest + requests) для проверки доступности эндпоинтов (если применимо).

## 7. Критерии начала и завершения
**Критерии начала (Entry criteria):**
- Доступ к тестовому стенду (saucedemo.com) имеется.
- Известны учетные данные для входа.

**Критерии завершения (Exit criteria):**
- Пройдены все запланированные тест-кейсы.
- Обнаруженные дефекты задокументированы в баг-трекере (в виде Markdown-файлов).
- Составлен итоговый отчет (в данном случае — README проекта).

## 8. Риски
- Внезапное обновление интерфейса SauceDemo может привести к неактуальности тест-кейсов.
- Специфичные баги под аккаунтом `problem_user` могут быть неочевидны при поверхностном тестировании.
